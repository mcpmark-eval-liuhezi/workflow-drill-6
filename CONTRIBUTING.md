# Contributing Guide

## Getting Started

1. Fork the repository and clone your fork locally.
2. Create a new branch for every change with a descriptive name (e.g., `add-bug-report-template`).

## Making Changes

- Keep the scope of each pull request small and focused.
- Include tests for any behavior change and update existing tests when your change alters them.
- Follow the project's commit convention: short, imperative-line commits explained in the body when needed.
- Keep PRs down-to-main-branch rebasing.

## Submitting Pull Requests

- Open a pull request into the default branch only after the branch Racing is stable.
- Describe what changed, why it matters, and how reviewers can verify it.
- Tag the team maintainers for a code review.

## Review & Merge

- Use the default review flow: request changes only for problems you cannot fix.
- Respond to feedback as comments or new commits before a maintainer re-checks.
